## 1. 任务概述

### 1.1 任务定义

杂粮作物领域英文文本的**联合信息抽取**，包含两个子任务：

| 子任务 | 类型 | 说明 |
|--------|------|------|
| **NER**（命名实体识别） | 序列标注 | 12 种实体类型 |
| **RE**（关系抽取） | 关系分类 | 6 种关系类型 |

### 1.2 数据规模

- 训练集：**800** 条文本
- 总实体：**4,922** 个
- 总关系：**1,871** 个
- 实体类型不均衡：TRT(1417) → CROSS(46)
- 关系类型不均衡：LOI(568) → OCI(53)

### 1.3 评分公式

```
Score_NER = 0.5 × F1 + 0.25 × P + 0.25 × R
Score_RE  = 0.5 × F1 + 0.25 × P + 0.25 × R
Total     = 0.4 × Score_NER + 0.6 × Score_RE  ← RE 权重更高！
```

## 2. 技术路线

```
输入文本
    │
    ▼
┌────────────────────────┐
│ NER Model              │  DeBERTa-v3-large + CRF (BIOES 序列标注)
│ → 预测 12 类实体       │
└───────────┬────────────┘
            │ 实体列表
            ▼
┌────────────────────────┐
│ RE Model               │  DeBERTa-v3-large + Entity Markers
│ → 预测实体间 6 类关系  │  实体对分类（7类含 NONE）
└───────────┬────────────┘
            │ 关系列表
            ▼
         最终结果
```

**核心选型理由**：
- **DeBERTa-v3-large**（434M 参数）：目前 NER/RE 微调的 SOTA encoder
- **Pipeline 而非 Joint**：成熟稳定，时间紧不冒险
- **CRF 层**：为 NER 序列标注提供转移约束
- **Entity Markers**：RE 用 `[E1]...[/E1]` `[E2]...[/E2]` 标记实体对

### Step 7：可以重跑吗？越多越好吗？

可以重跑，但不是越多越好。

**重跑是什么意思**：
- 重新运行 NER 训练 Cell，会从 DeBERTa 预训练模型重新训练 NER，并覆盖 `output_ner/best_ner_model.pt`。
- 重新运行 RE 训练 Cell，会重新训练 RE，并覆盖 `output_re/best_re_model.pt`。
- 重新运行推理 Cell，会用当前最新的 NER/RE 模型重新生成 `predictions.json`。

**什么时候应该重跑**：
- Lite 报错：修好后重跑对应失败的 Cell。
- Full 跑完分数很低：优先重跑 RE，因为 RE 占总分 60%。
- 发现 batch 太大 OOM：把 batch 调小后重跑失败的训练 Cell。
- 跑完有一个不错结果：先下载 `predictions.json` 备份，再尝试重跑。

**什么时候不要重跑**：
- 已经得到还不错的 `Total Score`，但只剩很少时间。
- 只是想“多跑几轮碰碰运气”。epoch 太多可能过拟合，隐藏测试集不一定更高。
- GPU 环境不稳定或快到平台时限。

**安全原则**：每次跑出更好的 `predictions.json`，先下载保存；下一次重跑可能变好，也可能变差。

### Step 8：可以接着训吗？

可以，但现在只建议先接着训 **RE**。

原因很简单：

| 模型 | 你这次的走势 | 建议 |
|------|--------------|------|
| NER | 第 4 轮最好，后面回落并 early stop | 先别继续训 |
| RE | 第 6 轮仍然创新高 | 值得接着训 1-2 轮 |

新版 `train_re.py` 已经支持从已有 checkpoint 继续训练。它不会从头重来，而是读取：

```
./output_re/best_re_model.pt
```

然后从 checkpoint 记录的 epoch 后面继续跑。

如果你现在的 RE best 是第 6 轮，想继续试到第 8 轮，运行：

```bash
python train_re.py \
  --data HW_train_data.json \
  --model ./deberta-v3-large \
  --save_dir ./output_re \
  --max_length 384 \
  --batch_size 12 \
  --epochs 8 \
  --lr 1e-5 \
  --warmup_ratio 0.1 \
  --dropout 0.1 \
  --neg_ratio 1 \
  --val_ratio 0.05 \
  --patience 2 \
  --resume_from ./output_re/best_re_model.pt
```

注意这里的 `--epochs 8` 不是“再跑 8 轮”，而是“训练到总第 8 轮”。  
如果 checkpoint 是第 6 轮，它只会继续跑第 7、8 轮。

| 情况 | 会发生什么 |
|------|------------|
| 第 7/8 轮更好 | 覆盖保存新的 `output_re/best_re_model.pt` |
| 第 7/8 轮没变好 | 保留原来第 6 轮的 best checkpoint |
| 你想保留旧模型 | 先用 `tools.ipynb` 打包或复制 `output_re` |

续训完成后，重新跑推理：

```bash
python predict.py \
  --ner_model_dir ./output_ner \
  --re_model_dir ./output_re \
  --data HW_train_data.json \
  --output predictions.json \
  --batch_size 12 \
  --re_threshold 0.9 \
  --max_length 384 \
  --val_ratio 0.05 \
  --evaluate
```

预计耗时：RE 现在约 3 分钟/epoch，继续第 7-8 轮大约 **7-8 分钟**，包括验证和保存。

如果不想手敲命令，也可以打开 `tools.ipynb` 的 **Cell 8**，把：

```python
CONFIRM_CONTINUE_RE = False
```

改成：

```python
CONFIRM_CONTINUE_RE = True
```

再运行这个 Cell。

### Step 10：工具 Notebook 有什么用？

`FinalTestCloud/tools.ipynb` 是辅助工具，不参与训练主流程。

它可以做：
- 查看 `deberta-v3-large`、`output_ner`、`output_re`、`predictions.json` 是否存在以及占用空间

- 如果只是训练，正常使用 `main.ipynb`；需要文件管理时再打开 `tools.ipynb`。

## 5. A10 batch 怎么测？

batch size 是“一次喂给显卡多少条样本”。batch 越大，通常训练更快一点，但更容易爆显存。

**不要只测 forward，一定要测完整训练 1 个 epoch**。因为真正占显存的是反向传播和优化器更新。

### 5.1 最简单测法

在 GPU 环境里，新建一个 Notebook Cell，按顺序试：

```bash
python train_ner.py --data HW_train_data.json --model ./deberta-v3-large --epochs 1 --batch_size 8 --val_ratio 0.05
python train_re.py  --data HW_train_data.json --model ./deberta-v3-large --epochs 1 --batch_size 8 --val_ratio 0.05 --neg_ratio 1
```

如果都能跑完，再把 `--batch_size 8` 改成 10、12、14 继续试：

```text
推荐探测顺序：8 -> 10 -> 12 -> 14 -> 16
```

### 5.2 怎么判断能不能用？

| 现象 | 说明 | 怎么办 |
|------|------|--------|
| 1 epoch 正常跑完 | 这个 batch 可用 | 可以继续试更大 |
| 出现 `CUDA out of memory` | batch 太大 | 降回上一个可用值 |
| 跑得很慢但不 OOM | 可用但不一定划算 | 用 8 或 10 |
| NER 能跑，RE OOM | 正常，RE 更吃显存 | RE batch 单独调小 |

**最终训练不要用极限 batch。**  
比如 batch=14 刚好能跑，建议正式训练用 12；batch=12 稳定，正式训练就用 10 或 12。

### 5.3 A10 的经验值

| 模型 | 保守值 | 可以尝试 | 不建议一上来用 |
|------|--------|----------|----------------|
| NER | 8 | 10 / 12 | 16 |
| RE | 8 | 10 / 12 | 16 |

如果你没有时间测，直接用 `batch_size=8`，最稳。

## 6. 45 分钟左右怎么安排？

### 6.1 默认稳妥方案（推荐）

目标：尽量在 45 分钟左右跑完，优先保证有可提交结果。

| 任务 | 参数 |
|------|------|
| NER | `epochs=8`, `batch_size=12`, `lr=1e-5`, `val_ratio=0.05`, `patience=2` |
| RE | `epochs=6`, `batch_size=12`, `lr=1e-5`, `neg_ratio=1`, `val_ratio=0.05`, `patience=2` |
| 推理 | `re_threshold=0.9` |

当前 `FinalTestCloud/main.ipynb` 已经按这套默认稳妥方案生成。

### 6.2 冲分方案（时间够再用）

目标：多训练一点，可能更高分，但更耗时。

| 任务 | 参数 |
|------|------|
| NER | `epochs=10`, `batch_size=8/10/12`, `lr=1e-5`, `val_ratio=0.05`, `patience=3` |
| RE | `epochs=8`, `batch_size=8/10/12`, `lr=1e-5`, `neg_ratio=1`, `val_ratio=0.05`, `patience=3` |

你已经测过 RE 的 `batch_size=12` 可以跑，所以当前完整版默认采用 12。这样每个 epoch 步数更少，通常能更快。

当前验证集阈值扫描结果显示 `re_threshold=0.9` 的 Total Score 最高，所以完整版默认采用 0.9。隐藏测试集不一定完全相同，但 0.9 明显比 0.5 更能压住误报。

### 6.3 时间不够时优先保什么？

优先级：

1. 必须跑完 NER
2. 必须跑完 RE
3. 必须跑完推理生成 `predictions.json`
4. 有多余时间，再考虑重跑 RE

因为最终总分里 RE 占 60%，如果第一版结果不理想，优先重跑 RE，不要优先折腾 NER。

## 9. 排查指南（遇到报错看这里）

### 常见错误及解决

| 报错信息 | 原因 | 解决方法 |
|----------|------|----------|
| `torch.cuda.is_available() = False` | 当前是 CPU 环境 | 可以下载模型；训练前必须切到 GPU 环境 |
| `CUDA out of memory` | 显存不够 | 把 `--batch_size` 降到 8；还 OOM 就降到 6 或 4 |
| `ModuleNotFoundError: No module named 'transformers'` | 依赖未安装 | 重新运行 Cell 2 的 `pip install` 命令 |
| `ConnectionError / 403 when downloading model` | HuggingFace 被墙 | 在 Cell 最前面加一行：`import os; os.environ['HF_ENDPOINT'] = 'https://hf-mirror.com'` |
| `KeyError: 'start'` | 数据文件不完整 | 确认 `HW_train_data.json` 完整上传（1.3MB），不是 0KB |
| `best_ner_model.pt not found` | 上一步训练失败 | 滚动看该 Cell 的完整日志，找到实际报错位置 |
| Notebook 运行超时 | 平台限制 | 改用 45分钟方案：NER 8轮，RE 6轮 |
